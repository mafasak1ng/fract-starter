# Technical Index

## Purpose

The technical domain holds reusable technical knowledge: how a tool works, how a format is structured, how you solved a problem that may come back, and the design of the code that lives in this vault.

## What belongs here

- How-to notes and troubleshooting records you will reuse.
- Design notes and data models for the scripts under `code/`.
- Comparisons of tools or approaches, with the evidence behind the choice.

## What does not

- Machine-specific setup (that is `30-infrastructure`).
- Code itself: notes link to code, they do not paste large blocks of it.
- Business decisions about tools (those belong in `60-business` when they are about money or clients).

## Naming

Name notes after the topic and the angle: `Git - Recovering a Bad Merge.md`, `Validator - Data Model.md`. Prefer the term a search would use.

## Example

`40-technical/Validator - Data Model.md`, type `data-model`: the fields the validator reads from each note, the checks applied to each, and which checks are errors or warnings.
